# 自动识别底图：方案与推进记录

> 这份文档是「让用户少手工搭题面」这条线的**唯一权威记录**。上下文丢失后请先读它。
> 最后更新：2026-10-11

## 1. 目标与非目标

**目标**：用户导入一张地图（PDF / 截图 / 扫描件 / 拍照）后，程序**自动**完成：
底图对位、区域划分、物品及其占格、人物名与关联，尽量省掉手工搭建。

**非目标 / 明确约束**：
- **识别永远只产出「候选」**，用户在棋盘上确认/微调后写入（可撤销）。手动兜底永远存在。
- **不维护服务器、不付算力费**：一切在浏览器里跑（静态托管或 `file://`）。
  大模型只在「用户自带 key」时可选启用，且默认关闭。
- 不追求一次识别全对；追求「省掉大部分手工 + 错了也不会把题面做错」。

## 2. 核心架构：输入适配器 + 统一栅格管线

```
输入适配器（只负责产出"好栅格 + 可选提示"）
├─ PDF      → pdf.js 渲染指定页            hints: 文字层(精确坐标)/矢量路径/图标 XObject
├─ 截图/图片 → 直接解码（粘贴/拖拽/选文件）  hints: 无
├─ 扫描件   → 同截图，通常更干净             hints: 无
└─ 拍照     → 先单应矫正，之后同截图         hints: 无
        ↓
统一栅格管线（唯一实现，与来源无关）
  0 预处理：去噪 / 暗色反转检测 / 光照归一化(照片) / 降采样
  1 几何：网格线检测 → pitch / 原点 / 倾角（P0.5 再加单应）
  2 语义提取（按可用性降级）
       ① 文字层(PDF)  ② 局部 OCR(截图/扫描)  ③ 纯视觉(颜色/纹理/形状)
  3 候选题目 JSON → 预览叠加 → 用户确认 → 走现有导入通道写入
```

**已有实测结论（重要）**：这两份官方 PDF **都有完整文字层**（`car-repair-color.pdf` 91 块、
`contest1` p1 173 / p2 108 块）——区域名、物品名、人物名、线索、`R1..R24/C1..C24` 全是带坐标的真文本。
**所以 PDF 不要 OCR**：整页 OCR 实测字符准确率仅 30-40%（装饰字体+纹理背景），文字层是 100% 且免费。

## 3. 已确认的决策

| 决策 | 内容 |
|---|---|
| 底图模型 | **保持单张**，只放**网格地图**部分（要参与对齐的只有它） |
| 图例/人物说明 | 放**右侧卡片**（现有 snipper，已支持多张/缩放/排序/持久化）；只需给卡片加轻量 `role`（图例/线索/其他） |
| 识别素材 | 识别时**按需读卡片**；识别结果不写回卡片（卡片是用户私人物品，删了不影响已识别结果） |
| 分析分辨率 | **导入时立刻分析**（原图/File 还在内存里），用**全分辨率**；压缩版(1600px)只用于显示/存档 |
| 地图被裁切 | 对位锚定在**可见网格**上（第一条检测到的线未必是 R1）；行列数由用户确认 |
| 不做 | 多底图图层（暂不做）；透视对位（P0.5）；视口大模型（可选、自带 key） |

## 4.5 P0 进度（2026-10-11）

**已完成**：几何模块 `js/align.js`（纯 JS、无依赖、Node 可测）+ 单测 `tests/align.test.js`。

算法链：降采样 → 局部背景求墨迹 → **行程长度平方加权投影**（只认长直线，纹理/文字/图标被压掉）
→ Otsu 阈值 → 归一化自相关取候选周期 → **墨迹捕获率**定周期（不受线强弱不均影响）
→ 梳状取最大精修相位 → 亚像素线位 → 最小二乘拟合 pitch/原点/倾角 → 置信度。
倾角用**投影集中度**估（网格摆正时投影最锐）；x/y 格距必须接近（正方形一致性）才算可用。

**合成图单测 8/8 通过**：干净网格、光照渐变、±18 灰阶噪声、整图旋转 2°、被裁切的地图、
纯噪声/纯白必须明确失败、真实感地图（区域纹理 + 图标 + 图例文字干扰）、性能。
真实感用例：pitch=80 精确，对比度 40、覆盖 1.0、置信度 1.0。

**真实 PDF 渲染图（4× 渲染，分析前降到 1400px 长边）**：

| 页 | 结果 | 判断 |
|---|---|---|
| `car-repair-color` p1 | ok，pitch x=70.49 / y=70.44，置信度 0.661 | ✅ 可用（15×11 可见网格） |
| `contest1` p1（人物卡页） | ok=false「x/y 格距不一致」 | ✅ 正确拒绝（不是地图页） |
| `contest1` p2（24×24 地图页） | ok，pitch x=**33.50** / y=**33.51**，置信度 0.794 | ✅ 2× 谐波已修（真值约 34） |

**已修（2026-10-11 晚）**：地图页把格距报成 2 倍。修法与原因：

1. **候选举不全**：真周期可能根本没进自相关候选（区域粗边框会让"隔一条线"的结构更强），
   所以候选里显式加入每个自相关峰的 /2、/3。
2. **判据不区分谐波**：换成 **`min(命中率, 捕获率)` 取最大** —— 约数（p/2）捕获率满分但
   一半梳齿落在空处（命中率腰斩），整倍数（2p）命中率满分但漏掉一半线（捕获率腰斩），
   只有基本周期两者都高。并列取最小 pitch。
3. **"有墨"判据必须是相对的**：横线会在每一列都留一丁点墨，`prof[i] > 0` 会让命中率永远
   满分；改成 `> 1.5 × 均值`。
4. **抛物线精修要夹住偏移**（±0.5）：`den ≈ 0` 时偏移会爆掉，pitch 变负 → 下游按 pitch
   步进的循环死循环（真把测试挂死过）。
5. **伪倾角要防**：光照渐变会估出个小角度，旋转重采样反而把线抹开 → 改成旋转前后各分析
   一次、按"两个方向都成立且置信度高"取更好的。
6. **对比度门槛 1.35 → 2.0**：纯噪声只有 1.44，会被误判成网格。
7. **用一个方向的范围限制另一个方向**：地图常只占画面一部分，图例/文字会把另一方向的
   周期带偏（`runProfile` 支持 bounds）。
8. `ratio` 门槛 0.6 → 0.4：真实地图页只有 17/30 条线足够明显，但对比度 14、两轴一致。

**剩余已知问题**：`car-repair-color` p1 的 y 方向被页面上的文字行带成半格距（x=70.49 ✓、
y=35.00 ✗，因此报"x/y 不一致"而拒绝）。这正是 **P0.1「框选地图范围」**要解决的场景——
识别只在该区域里统计；在框选功能做出来之前，这一页按"检测失败，请框选"处理即可。

**还没做**：接入 app（导入时全分辨率分析、「自动对位」按钮、失败提示、框选地图）、
把 `js/align.js` 注册进 `index.html`、e2e。

## 5. P0 详细设计

### 5.1 算法（纯 JS，无依赖，Node 可单测）

```
输入 raster = { data: Uint8ClampedArray(RGBA), width, height }, opts
1 降采样：最长边 ≤ ~1600，盒式平均（同时得到灰度 luma 与缩放比）
2 墨迹图 ink = clamp(背景 - luma, 0, 255)
    背景 = 大核盒式模糊（滑动窗口 O(W·H)）→ 对不均匀光照/照片鲁棒
3 投影：列方向累加 ink → profX；行方向 → profY
4 周期：自相关找候选 pitch（首个强峰，避免谐波）→ 再用"梳状打分"
    score(p,φ) = Σ prof[φ + k·p] 对每个候选 p 与相位 φ 求最优 → 取最高分
5 峰值精修：在 k·p+φ 附近窗口内取 ink 加权质心 → 亚像素线位；峰值太弱记为"缺线"
6 最小二乘拟合「线序号 → 线位置」→ pitch、原点、倾角；残差 RMS = 置信度
7 旋转：先由梯度方向直方图（Sobel）估计主方向（mod 90°），必要时重采样后再走 3-6
8 结果：pitch/origin/angle/可见行列数(lines)/confidence/ok
```

### 5.2 API（拟）

```js
MurdokuAlign.detectGrid(raster, { minPitch = 8, maxPitch = 400, analyzeSide = 1600 })
// → { ok, confidence, pitch: {x, y}, origin: {x, y}, angle, lines: { x: [...], y: [...] },
//     cols, rows, stats }
MurdokuAlign.toBackground(det, { cellSize, grid })   // 换算成 app 的 scale / grid.x / grid.y
```
