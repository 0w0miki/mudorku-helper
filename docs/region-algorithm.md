# 区域识别算法：现状拆解与改进方案

> 目的：把 `js/regions.js` 里"现在到底在算什么"写清楚，再按**收益 ÷ 风险**排改进项。
> 配套：`docs/auto-extract-plan.md`（§4.7–4.8 是推进记录）、`tests/regions.test.js`（现有夹具）。

## 0. 一句话概括

```
逐格取样（颜色 + 纹理） → 给每条相邻边打一个"这里是隔墙"的分 → 用区域名当种子把格子切成 k 块
→ 在 4 个候选划分里挑打分最高的 → 逐格局部搜索微调 → 输出候选区域
```

没有任何机器学习，也没有绝对颜色阈值；**唯一的"硬知识"来自图上的区域名**（k 与种子位置）。

## 1. 数据流总览

| # | 步骤 | 代码 | 输入 → 输出 | 关键参数 | 已知失效 |
|---|---|---|---|---|---|
| 0 | 取样 | `sampleCells` `js/regions.js:45` | raster+geom → 每格 {lab, rgb, edge, grad} | `inset 0.28`、`pad 0.07`、强梯度阈值 **90** | 绝对梯度阈值；越界格直接丢弃（不归属任何区域） |
| 1 | 边的隔墙证据 | `borderProbe` `:165` | 两格 → {coverage, width, depth, darkFrac, bold} | `span 6px`、`samples 9`、`depthAbs 22`、`depthRel 0.09`、`minWidth 3px` | **饱和**（width≥6 → 因子=1、coverage=1 → wall=1.0）；家具贴格界 → 假墙 |
| 2 | 边代价 | `:265` `:274` | → `cost = cellDistance + wall*300` | 墙项权重 **300** vs 色距典型 0–40 | 墙饱和后合并顺序基本由微小色差决定 |
| 3 | 种子合并 | `:285`–`:326` | 种子 → 恰好 k 块（层次合并，平均代价最小优先） | 硬约束"双方都有名字不许合并" | 只保证 k，不保证边界落在墙上 |

| 8 | 无种子回退 | `:443`–`:568` | 颜色/粗线自适应 + Otsu | `boldRatio ≥ 0.06` 判"靠墙分区" | 只用于读不到区域名的情况 |

## 2. 关键公式

**取样（每格）**：在"格内一圈"（避开中心 28% 与贴线 7%）统计 RGB 直方图 → **中位数**为格子颜色 → 转 Lab；
`edge = 强梯度像素占比`（|∇|>90）。

**格间色距**：`√(ΔL² + 2.4Δa² + 2.4Δb² + 400Δedge²)`（色度权重 2.4，纹理权重 400×Δedge²）

**隔墙判据**（每条共享边取 9 个截面，每个截面是跨线 ±6px 的亮度剖面）：
```
need   = max(22, 0.09 × 两格平均亮度)        ← 暗到多少算"墙"
暗游程 = 连续 < (格亮度 − need) 的像素数
算墙   = 暗游程 ≥ 3px 且 最深 ≥ need
coverage = 算墙的截面数 / 9
wall     = coverage × clamp((最宽游程 − 2) / 4, 0, 1)      ← 0~1
bold     = coverage ≥ 0.6
```

**划分打分**：`score = mean(wall | 跨界边) + 0.02 × mean(色距 | 跨界边)`

**层次合并**：反复合并"平均 `cost` 最小"的两个分量，直到剩 k 块。

## 3. 用你的实测数据核对：为什么现在会偏

你给的 `familymurdoku`（7×7，格距 81.9）诊断：

| 观察 | 说明什么 |
|---|---|
| 84 条相邻边里 **53 条 wall ≥ 0.9** | **证据饱和**：`wall` 挤在 1.0，打分里"平均 wall"几乎是常数 → 排序实际由 0.02×色距决定 → 容易拼出竖条 |
| 区域之间的边界全 `wall 1.00` | 真边界能被看见 → **信息是有的，是被平均化浪费了**；也说明"用边界证据给划分打分"方向对 |
| 区域内部也有 `wall 1.00`、色差仅 2.5 | 家具/课桌贴着格界 → 假墙。`darkFrac` 已经算出来了但**没有参与判定**（当年试过用它判定，car-repair 回退过） |
| 整体**偏一行** | 与形状算法无关：pdf.js 给的是文字**基线**坐标，视觉中心在基线上方约半格 → 种子格整体偏一格 |
| car-repair 的分界方向错 | 很可能就是 `candidateBands` 取"第一个合法组合"造成的（见 §4.1） |

结论：**先修证据层（让它不再饱和、能区分真假墙），再修种子层（偏一格），划分层最后动。**

## 4. 真 bug 与隐患

### 4.1 `candidateBands` 取第一个合法组合，而不是最好的（`js/regions.js:624`）
```js
if (ok && !bestOk) { best = assign; bestOk = true; }   // ← 谁先合法就选谁
```
组合是按分界线位置**字典序**枚举的 → 永远偏向"切得最靠上/靠左"的那种。应改为对每个
合法组合算边界代价、取最优（组合数 ≤4000，可用前缀和做到 O(1)/组合）。这是 car-repair
方向错的**首要嫌疑**，而且修起来最便宜。

### 4.2 无法采样的格子会凭空消失（`js/regions.js:74`、`:100`）
越界/过小的格子标 `ok:false` 后不进 `list`，于是**不属于任何区域**（不是被分给邻居）。
后果：换底图/裁切后边缘格可能整行消失，用户看到"区域缺一角"。应把这类格子吸附给相邻分量。

### 4.3 Voronoi 用"格数距离"，与格距比例无关（`:584`）
`(r−sr)² + (c−sc)²` 假设格子是正方形且无旋转。格距不等或底图有轻微透视时，Voronoi 候选会系统性偏。
改成像素/格距归一距离（`((r−sr)·pitchY)² + ((c−sc)·pitchX)²`）只是一行。

### 4.4 `refinePartition` 每次试搬都全量重算（`:647`）
O(轮数 × 格数 × 4 × 边数)：7×7 可忽略，20×20（400 格、1520 边）≈ 2×10⁷ 次 → 明显卡顿。
改成**增量**（只重算与该格相邻的边）→ 快 50~100 倍，顺带可以多做几轮/多起点。

### 4.5 阈值是像素与绝对亮度，不随格距/对比度走
`span 6px`、`minWidth 3px`、`depthAbs 22`、`强梯度 >90` 都是绝对值。格距 34（contest1）时 ±6px
是 ±18% 格宽（会探到邻格）；照片上阴影渐变就能满足 depth 22 → 假墙。

### 4.6 标签只取一个基线点，没有宽度
`readRegionLabels`（`js/panels.js:695`）只保留 `x, y, h`，丢掉文字宽度。一个区域名"FRONT AREA"
其实横跨 2~3 格，这些格**确定**属于该区域——现在只用了其中一个点，还因为基线偏移可能偏一格。

## 5. 改进方案

### 5.1 证据层（收益最大，建议先做）

**A. 墙 = "有回落的暗谷"，不是"暗"**
一条真的隔墙剖面长这样：`亮 … 暗(3~8px) … 亮`；大块家具/阴影长这样：`亮 … 暗到底`（一端不回落）。
现在只看"有没有连续暗像素"，两者都算墙。加一条**回落判据**：
```
两端亮度 ≈ 格亮度（|差| < 0.15×need 或 < 12）
暗谷中心落在格界 ±0.06 格内
⇒ 才算墙
```
预期：把"家具造成的假墙"从 1.00 压到 0.2 以下 → 打分立刻有区分度。

**B. 每格自己的对比度尺度**
`sampleCells` 顺便输出该格环上的亮度 **MAD / p10–p90 展布**，判据改成
`need = max(depthRel × 格亮度, 2 × MAD)`。家具/纹理重的格子自带高展布 → 需要更深的暗谷才算墙，
不需要任何新的魔法常数。

**C. 几何按格距归一**
`span = clamp(0.08 × pitch, 4, 12)`、`minWidth = max(2, 0.04 × pitch)`、横截面位置同样按 pitch 取。
一张图在不同缩放/分辨率下结论一致（照片、不同行列数都不用重调）。

**D. 补一条与颜色无关、与亮度也无关的证据：两侧独立同色**
对一条边，比较"格的内部颜色"与"紧贴边界两侧各 2px 的颜色"：
若两侧贴边色都 ≈ 各自格子色，而中间有暗带 → 线；若一侧贴边就已经是暗的 → 大块暗区（不是线）。

> 注：**不要再走"调固定阈值"的路**（历史上 f079c47 用 0.4/0.6 补全墙线，反而更差，已回退）。
> 这一节所有改动都应该在 §6 的离线夹具上先量出准确率再合。

### 5.2 种子层（修"偏一行"）

**E. 用标签的 bbox，而不是一个基线点**
pdf.js 的 item 有 `width`（和 `transform` 缩放后的宽度）。取文字外接矩形 → 与网格求交 →
把这些格子都标成该区域的种子（至少用 bbox **中心**那一行）。一举三得：修 ±1 行偏移、
种子更稳、k 更可靠。

**F. 种子偏移搜索（数据驱动，不猜）**
把全部种子整体平移 `dr, dc ∈ {−1,0,1}` 共 9 种，各自跑一遍"候选 + 打分"，取分数最高的偏移。
7×7 网格上每种只要几毫秒 → 总代价可忽略。**这条能在不改任何阈值的前提下把"偏一行"自动修掉**，
而且它对"基线 vs 视觉中心"这类不确定性是免疫的（不依赖我们猜对 pdf.js 的坐标语义）。

**G. 落格外的标签吸附 + 一致性报警**
标签落在网格外 → 吸附到最近的格（而不是丢弃，丢弃会让 k 变小、两块被强行合并）；
若最终识别出的区域里有"一个区域含两个种子"或"某个种子独占一格被围住" → UI 明确提示
「区域名 X 可能没对上，请核对」，而不是静默给出错误候选。

### 5.3 划分层

**H. 打分从"平均"改成"绝对和 + 非墙惩罚"**
现在是 `mean(wall)`：一个划分只要把边界放在**少数**几条墙上，平均就能很高。改成
```
cost(划分) = Σ_跨界边 [ (1 − wall) + α · exp(−色距/20) ]        // 越小越好
```
即"跨界边越少、越落在墙上越好"——长边界穿过无墙区域会被累加惩罚。这才是"墙把地图切成块"
这件事的正确能量函数（等价于一个带终端约束的**最小割**）。

**I. 真·全局划分：终端约束的多路割（min-cut）**
把每个种子当作终端（必须留在自己那块），每条边给出代价 → 求最小代价划分。
k ≤ 8、格数 ≤ 400，用 **Dinic 最大流 + α-expansion** 实现（纯 JS，约 150 行，无依赖），
几十毫秒出结果，**可以整体取代** 层次合并 + 平滑 + 4 个候选 + 局部搜索（现在这套 5 个部件）。
好处：全局最优（或 2-近似）、没有"候选挑不到"的问题、可解释（割的容量就是不可信度）。
风险：是新代码，必须先在夹具上证明比现状好再切换（保留旧路径做 fallback）。

**J. 先修 `candidateBands` 的 bug**（§4.1）：即使不改 H/I，这一步也可能直接修好 car-repair 的方向。

**K. `refinePartition` 增量打分**（§4.4）：性能上台阶，之后才敢在 20×20 上做多起点重启。

### 5.4 结果层（贴合"只给候选 + 人工兜底"的定位）

**L. 每个区域给一个置信度**：`边界墙证据的分布 + 面积 + 与种子的距离` → UI 上把可疑区域标黄，
不用用户自己看诊断文本猜。

**M. 标签质心 vs 区域质心一致性检查**：`TEACHER'S AREA` 的标签落在区域的边角甚至区域外 →
明显说明这次划分不对 → 明确报警（现在只在诊断里打印坐标，需要人肉比对）。

**N. 可解释性**：输出"哪几条边决定了这次划分"（割集），诊断文本里直接列出 TOP-N 条割边及其
wall/色差，用户一眼能看出错在哪。

## 6. 评测先行（最该先做的一件事）

现在之所以只能靠来回试，是因为**没有一张带真值的真实图**：

- 现有合成夹具（`tests/regions.test.js:235`）的家具画在格内 +20px 处，而探针窗口只有 ±6px
  → **合成图里根本不存在"家具贴格界"这个真实失效模式**，所以 100% 准确率不能说明真实地图也准。
- 建议：把 `familymurdoku` 的**地图区域**裁图（不是整页）导出成 `tests/fixtures/family-map.png`
  （几百 KB），配上你给的真值（7×7 的 1/2/3），再加一个 `tests/region-truth.js`：
  ```
  node tests/region-truth.js            # 输出：格准确率、混淆矩阵、每格的墙/色差、候选分数、耗时
  ```
  技术上可行：用已有的 Playwright + 应用本身把 PDF 渲染成栅格，再裁到地图外框导出 PNG（一次性）。
- 验收线（建议）：
  1. 格准确率 ≥ **95%**；
  2. 「真边界的平均 wall」比「同区域内伪墙的平均 wall」高 ≥ **0.25**（现在这条是 0 —— 两边都 1.00）；
  3. wall 直方图**双峰**（Otsu 类间方差占总量 ≥ 0.6），而不是一堆挤在 1.0。

第 2 条是这次的核心指标：它衡量的是"证据有没有区分度"，而不是"这次蒙对没有"。

## 8. 不变的原则（来自项目已有决策）

- 识别只出**候选**，手动路径永远存在，一切可 ⌘Z 撤销。
- **不引入服务器、不花算力**；纯静态、无运行时依赖、Node 可单测。
- 不猜固定阈值；参数一律"从这张图自己的分布里量出来"（Otsu/分位数/每格统计量）。
- 宁可明确报警，也不要静默给出错误结果。
